# Code of Conduct

## In short

Be decent. Criticise code, not people. Assume the person on the other side is
acting in good faith until they clearly are not.

## What is expected

- **Focus on the work.** "This function can panic on empty input" is useful.
  "This is amateur work" is not, and it is not more true for being blunter.
- **Take disagreement about technical decisions seriously.** Most of this
  project's design choices are trade-offs, and someone arguing the other side is
  doing you a favour. Argue the trade-off, not the person making it.
- **Be patient with questions.** Cryptography and file formats are areas where
  people are reasonably afraid of looking foolish, which is exactly how bugs go
  unreported.
- **Respect people's time.** Read `CONTRIBUTING.md` before opening a pull
  request; search before opening an issue.

## What is not acceptable

Harassment, insults, discriminatory remarks, sexual attention or advances,
publishing anyone's private information, deliberate intimidation, or sustained
disruption. This holds in issues, pull requests, commit messages, code comments,
and any other project space.

## Scope

Applies to everyone in every project space, including anyone representing the
project elsewhere.

## Enforcement

Report a problem privately to the maintainer through
[GitHub](https://github.com/gh0st032395) — a direct message, or a private
security advisory if the ordinary channels are not appropriate. Reports are
handled confidentially.

The maintainer may warn, remove content, or block a participant, in proportion
to what happened and whether it continues. There is no appeals bureaucracy for a
project this size: there is one person trying to be fair, who will explain the
reasoning for any action taken.
